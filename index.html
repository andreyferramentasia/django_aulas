Parte I

Preparação do Ambiente

1

Passo 1

Criar a pasta do projeto
  1. Abra o Explorador de Arquivos (Win + E).
  2. Crie uma nova pasta.
  3. Dê um nome e pressione Enter.

Dica

Sem espaços ou acentos: meu_projeto

2

Passo 2

Criar o ambiente virtual
  1. Abra o terminal dentro da pasta do projeto.
  2. Execute o comando:

Terminal

> python -m venv .venv

Dica

A pasta .venv guarda as bibliotecas só deste projeto.

3

Passo 3

Ativar o ambiente virtual

A Automático, VS Code

A extensão Python ativa a .venv sozinha ao abrir um novo terminal.

B Manual

PowerShell

> .venv\Scripts\Activate.ps1

CMD

> .venv\Scripts\activate

! Erro de permissão no PowerShell?

Ajuste a política de execução do Windows:

PowerShell · só este terminal

> Set-ExecutionPolicy -Scope Process -ExecutionPolicy RemoteSigned

PowerShell · permanente para o usuário

> Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned

Ainda com problema?

Use o CMD em vez do PowerShell.

CMD

> .venv\Scripts\activate.bat

Funcionou?

O terminal passa a mostrar (.venv) no início da linha.

4

Passo 4

Instalar as bibliotecas

Com a (.venv) ativa, execute:

Terminal

> python.exe -m pip install --upgrade pip
> pip install django
> pip install django-jazzmin==3.0.1

Atenção

Use a versão 3.0.1 do Jazzmin, versões mais novas estão com problemas.

✓ Verificar a instalação

Terminal

# Versão do Python
> python --version

# Versão do Django
> django-admin --version

# Versão do Jazzmin
> pip show django-jazzmin

# Todas as bibliotecas instaladas
> pip list

Parte II

Criação do Projeto

5

Passo 5

Iniciar o projeto

Terminal

> django-admin startproject app .

Atenção ao ponto

O . cria o projeto na pasta atual, sem gerar uma pasta extra.

✓ Estrutura gerada

Pasta do projeto

meu_projeto/
├── .venv/
├── app/
│   ├── __init__.py
│   ├── asgi.py
│   ├── settings.py
│   ├── urls.py
│   └── wsgi.py
└── manage.py
6

Passo 6

Rodar o servidor

Com a (.venv) ativa, execute:

Terminal

> python manage.py runserver
  1. Acesse http://127.0.0.1:8000 no navegador.
  2. Para parar o servidor: Ctrl + C

✓ Resultado esperado

Banco de dados

Na primeira execução é criado o arquivo db.sqlite3 na pasta do projeto.

7

Passo 7

Primeira migração

Ao rodar o servidor, o terminal exibe este aviso:

Saída do runserver

You have 18 unapplied migration(s). Your project may not work properly until you apply the migrations for app(s): admin, auth, contenttypes, sessions.
Run 'python manage.py migrate' to apply them.
September 29, 2026 - 08:25:53
Django version 6.1.1, using settings 'app.settings'
Starting WSGI development server at http://127.0.0.1:8000/
Quit the server with CTRL-BREAK.
  1. Pare o servidor: Ctrl + C
  2. Aplique as migrações padrão do Django:

Terminal

> python manage.py migrate

O que acontece?

São criadas no db.sqlite3 as tabelas de usuários, sessões e do admin.

8

Passo 8

Criar o superusuário

Terminal

> python manage.py createsuperuser
Username (leave blank to use 'andrey'): admin
Email address: admin@admin.br
Password: # nada aparece ao digitar
Password (again): # nada aparece ao digitar
The password is too similar to the email address.
Bypass password validation and create user anyway? [y/N]: y
Superuser created successfully.
  1. Username: nome de acesso.
  2. Email: precisa ter formato de e-mail, com @ e terminando em .com ou .br.
  3. Password: senha e confirmação.

A senha não aparece

Ao digitar a senha, nada é exibido no terminal. É normal, digite e pressione Enter.

Senha fraca?

O Django avisa quando a senha é fraca, por exemplo:

  • The password is too similar to the email address. (parecida com o e-mail)
  • This password is too short. (curta demais)
  • This password is too common. (comum demais)

Em seguida pergunta Bypass password validation and create user anyway? [y/N]:

  • y (yes): cria o usuário mesmo assim.
  • N (no): cancela e pede a senha novamente. É o padrão ao apertar só Enter.

Em desenvolvimento, pode usar y. Em produção, use uma senha forte.

✓ Primeiro login

  1. Rode o servidor: python manage.py runserver
  2. Acesse http://127.0.0.1:8000/admin e entre com o usuário criado.

Ajustando o Jazzmin

1 Registrar o app

No arquivo app/settings.py, adicione 'jazzmin' no topo do INSTALLED_APPS:

app/settings.py

INSTALLED_APPS = [
    'jazzmin',
    'django.contrib.admin',
    'django.contrib.auth',
    'django.contrib.contenttypes',
    'django.contrib.sessions',
    'django.contrib.messages',
    'django.contrib.staticfiles',
]

Atenção

Não esqueça a vírgula depois de 'jazzmin'. Ele precisa vir antes do django.contrib.admin.

Parte III

Versionamento com Git

9

Passo 9

Instalar o Git
  1. Baixe o instalador em git-scm.com/install/windows
  2. Instale com as opções padrão.

✓ Verificar a instalação

Terminal

> git --version

Dica

Feche e abra o terminal novamente após instalar.

10

Passo 10

Criar o repositório no GitHub
  1. No GitHub, clique na sua foto (canto superior direito) e vá em Repositories.
  1. Clique em New.
  1. Preencha o Repository name * (campo obrigatório).
11

Passo 11

Criar o .gitignore

Lista os arquivos que o Git não deve enviar. Na pasta do projeto:

PowerShell

> ni .gitignore

Abra o arquivo e cole:

.gitignore

# Ambiente virtual
.venv/

# Cache do Python
__pycache__/
*.pyc

# Banco de dados local
db.sqlite3
db.sqlite3-journal

# Variáveis de ambiente (senhas, chaves)
.env

# Arquivos gerados pelo Django
media/
staticfiles/

# Logs
*.log

# Editores
.vscode/
.idea/

Atenção

Crie o .gitignore antes do git init e do primeiro commit, assim a .venv nunca é enviada.

12

Passo 12

Iniciar o Git no projeto

Na pasta do projeto, execute:

Terminal

> git init
Initialized empty Git repository in C:/.../meu_projeto/.git/

O que acontece?

É criada a pasta oculta .git, onde o Git guarda o histórico do projeto.
