O ModelForm cria um formulário a partir do model: os campos, rótulos e validações vêm prontos. Crie o arquivo forms.py dentro do app:

from django import forms
from courses.models import Course  # troque courses pelo nome do seu app


class CourseForm(forms.ModelForm):
    class Meta:
        model = Course
        fields = [
            "name",
            "description",
            "workload",
            "period",
            "teacher",
            "material",
            "image",
        ]
forms.ModelForm
Formulário ligado a um model. Salvar o formulário grava no banco.
model
Model usado para montar o formulário.
fields
Campos exibidos no formulário, na ordem da lista. Os rótulos vêm do verbose_name de cada campo.

? Cada campo vira um tipo de entrada

Campo no modelNo formulário
CharFieldCaixa de texto
TextFieldCaixa de texto grande
PositiveIntegerFieldCampo de número
choicesMenu com Matutino, Vespertino e Noturno
ForeignKeyMenu com as pessoas cadastradas
FileField e ImageFieldBotão de escolher arquivo

Menu de professor vazio?

O menu do teacher lista as pessoas do banco. Cadastre pelo menos uma pessoa no /admin antes de criar um curso.

Por que um forms.py?

Com o formulário separado, a mesma classe serve para criar e editar, e dá para personalizar widgets e validações num lugar só.

A CreateView é a view genérica de cadastro: mostra o formulário vazio, valida o que foi digitado e grava um registro novo no banco.

1 A view

from django.urls import reverse_lazy
from django.views.generic import ListView, CreateView
from courses.forms import CourseForm  # troque courses pelo nome do seu app
from courses.models import Course


class CourseListView(ListView):
    ...


class CourseCreateView(CreateView):
    model = Course
    form_class = CourseForm
    template_name = "courses/course_form_create.html"
    success_url = reverse_lazy("courses:course_list")
form_class
Formulário usado, o CourseForm do passo anterior.
template_name
Página do cadastro, course_form_create.html, criada no próximo passo.
success_url
Para onde ir depois de salvar, aqui a lista de cursos.
reverse_lazy
Transforma o name da rota em URL. É "lazy" porque as rotas ainda não existem quando a classe é lida.

2 A rota

from django.urls import path
from courses.views import CourseListView, CourseCreateView  # troque courses pelo nome do seu app

app_name = "courses"

urlpatterns = [
    path("listar/", CourseListView.as_view(), name="course_list"),
    path("criar/", CourseCreateView.as_view(), name="course_create"),
]

O passo 26 em vídeo.

Um HTML simples, só com o título e o formulário. O {{ form.as_p }} desenha os campos sozinho.

1 A página de cadastro

{% extends "base.html" %}

{% block title %}Novo curso{% endblock %}

{% block content %}
    <h1>Novo curso</h1>
    <form method="post" enctype="multipart/form-data">
        {% csrf_token %}
        {{ form.as_p }}
        <button type="submit" class="btn btn-primary">Salvar</button>
    </form>
{% endblock %}

2 Link de cadastro na lista

No course_list.html do passo 23, logo abaixo do <h1>:

<h1>Cursos</h1>
{# troque courses pelo nome do seu app #}
<a href="{% url 'courses:course_create' %}" class="btn btn-warning">Novo curso</a>

? Entendendo o código

Por que fora do for?
Tudo que está dentro do {% for course in courses %} se repete uma vez para cada curso. Se o botão ficasse lá dentro, com 10 cursos apareceriam 10 botões Novo curso. Ele fica fora, logo abaixo do <h1>, porque cadastrar não depende de nenhum curso da lista: é um botão só, e não precisa de pk. Já Editar e Excluir ficam dentro do for, porque cada curso precisa do seu.
method="post"
Envia os dados para a mesma URL. A view valida, salva e redireciona para o success_url.
{% csrf_token %}
Proteção contra envios falsos de outros sites. Obrigatório em todo formulário post, sem ele o Django responde 403.
{{ form.as_p }}
Desenha cada campo dentro de um <p>, com rótulo e mensagens de erro.
enctype="multipart/form-data"
Obrigatório aqui, porque o CourseForm tem material e image. Sem ele, o formulário salva o curso, mas os arquivos não chegam ao servidor e ficam vazios.

Sem <html> e <head>?

Vêm do base.html, pelo {% extends %}. Por isso esta página já tem o Bootstrap, o menu e o rodapé, como a lista.
