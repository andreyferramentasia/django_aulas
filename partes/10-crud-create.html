O ModelForm cria um formulário a partir do model: os campos, rótulos e validações vêm prontos. Crie o arquivo forms.py dentro do app:

from django import forms
from nome_do_seu_app.models import Person


class PersonForm(forms.ModelForm):
    class Meta:
        model = Person
        fields = ["first_name", "last_name"]
forms.ModelForm
Formulário ligado a um model. Salvar o formulário grava no banco.
model
Model usado para montar o formulário.
fields
Campos exibidos no formulário. Os rótulos vêm do verbose_name de cada campo.

Por que um forms.py?

Com o formulário separado, a mesma classe serve para criar e editar, e dá para personalizar widgets e validações num lugar só.

A CreateView é a view genérica de cadastro: mostra o formulário vazio, valida o que foi digitado e grava um registro novo no banco.

1 A view

from django.urls import reverse_lazy
from django.views.generic import ListView, CreateView
from nome_do_seu_app.forms import PersonForm
from nome_do_seu_app.models import Person


class PersonListView(ListView):
    ...


class PersonCreateView(CreateView):
    model = Person
    form_class = PersonForm
    template_name = "nome_do_seu_app/person_form_create.html"
    success_url = reverse_lazy("nome_do_seu_app:person_list")
form_class
Formulário usado, o PersonForm do passo anterior.
template_name
Página do cadastro, person_form_create.html, criada no próximo passo.
success_url
Para onde ir depois de salvar, aqui a lista de pessoas.
reverse_lazy
Transforma o name da rota em URL. É "lazy" porque as rotas ainda não existem quando a classe é lida.

2 A rota

from django.urls import path
from nome_do_seu_app.views import PersonListView, PersonCreateView

app_name = "nome_do_seu_app"

urlpatterns = [
    path("pessoas/", PersonListView.as_view(), name="person_list"),
    path("pessoas/nova/", PersonCreateView.as_view(), name="person_create"),
]

Um HTML simples, só com o título e o formulário. O {{ form.as_p }} desenha os campos sozinho.

1 A página de cadastro

{% extends "base.html" %}

{% block title %}Nova pessoa{% endblock %}

{% block content %}
    <h1>Nova pessoa</h1>
    <form method="post" enctype="multipart/form-data">
        {% csrf_token %}
        {{ form.as_p }}
        <button type="submit" class="btn btn-primary">Salvar</button>
    </form>
{% endblock %}

Por que fora do for?
Tudo que está dentro do {% for person in people %} se repete uma vez para cada pessoa. Se o botão ficasse lá dentro, com 10 pessoas apareceriam 10 botões Nova pessoa. Ele fica fora, logo abaixo do <h1>, porque cadastrar não depende de nenhuma pessoa da lista: é um botão só, e não precisa de pk. Já Editar e Excluir ficam dentro do for, porque cada pessoa precisa do seu.
method="post"
Envia os dados para a mesma URL. A view valida, salva e redireciona para o success_url.
{% csrf_token %}
Proteção contra envios falsos de outros sites. Obrigatório em todo formulário post, sem ele o Django responde 403.
{{ form.as_p }}
Desenha cada campo dentro de um <p>, com rótulo e mensagens de erro.
enctype="multipart/form-data"
Necessário quando o formulário envia arquivos (ImageField, FileField). Sem arquivo não faz diferença, então pode deixar sempre.

Sem <html> e <head>?

Vêm do base.html, pelo {% extends %}. Por isso esta página já tem o Bootstrap, o menu e o rodapé, como a lista.
