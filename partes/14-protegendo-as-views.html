Agora que existem contas, dá para proteger as views do CRUD. São dois mixins, cada um responde uma pergunta:

LoginRequiredMixin
Está logado? Qualquer usuário logado entra, não importa quem seja. Quem não está logado vai para a tela de login.
PermissionRequiredMixin
Pode fazer isso? Além de logado, o usuário precisa ter a permissão indicada. Logado sem permissão recebe erro 403 (proibido).

? Quando usar cada um

SituaçãoUseExemplo
Todo usuário logado pode ver ou fazerLoginRequiredMixinUma página de perfil. Se for o único mixin do CRUD, qualquer usuário logado vê, cadastra, edita e exclui.
Só alguns usuários podem fazerPermissionRequiredMixinVer, cadastrar, editar, excluir
Qualquer um, mesmo sem contaNenhumLogin e cadastro de conta

1 Configurar os redirecionamentos de login

No fim do settings.py:

LOGIN_URL = "accounts:login"
LOGIN_REDIRECT_URL = "courses:course_list"  # troque courses pelo nome do seu app
LOGOUT_REDIRECT_URL = "accounts:login"
LOGIN_URL
Para onde vai quem tenta abrir uma página protegida sem estar logado.
LOGIN_REDIRECT_URL
Para onde o usuário vai depois de fazer login.
LOGOUT_REDIRECT_URL
Para onde o usuário vai depois de sair.

2 Atualizar as views

from django.contrib.auth.mixins import LoginRequiredMixin, PermissionRequiredMixin
from django.urls import reverse_lazy
from django.views.generic import ListView, DetailView, CreateView, UpdateView, DeleteView
from courses.forms import CourseForm  # troque courses pelo nome do seu app
from courses.models import Course


class CourseListView(LoginRequiredMixin, PermissionRequiredMixin, ListView):
    login_url = reverse_lazy("accounts:login")
    permission_required = "courses.view_course"
    ...


class CourseDetailView(LoginRequiredMixin, PermissionRequiredMixin, DetailView):
    login_url = reverse_lazy("accounts:login")
    permission_required = "courses.view_course"
    ...


class CourseCreateView(LoginRequiredMixin, PermissionRequiredMixin, CreateView):
    login_url = reverse_lazy("accounts:login")
    permission_required = "courses.add_course"
    ...


class CourseUpdateView(LoginRequiredMixin, PermissionRequiredMixin, UpdateView):
    login_url = reverse_lazy("accounts:login")
    permission_required = "courses.change_course"
    ...


class CourseDeleteView(LoginRequiredMixin, PermissionRequiredMixin, DeleteView):
    login_url = reverse_lazy("accounts:login")
    permission_required = "courses.delete_course"
    ...
Ordem das classes
Os mixins vêm antes da view genérica (CreateView, UpdateView...). Senão a página abre antes da verificação.
login_url
Para onde vai quem não está logado. O reverse_lazy transforma o nome da rota "accounts:login" no endereço da página de login. Na view, ele vale só para ela e tem prioridade sobre o LOGIN_URL do settings.py.
permission_required
A permissão exigida, no formato app.acao_model. O Django cria quatro para cada model, sozinho, no migrate: add_course, change_course, delete_course e view_course.
CourseDetailView
Só existe se você fez o extra da DetailView na parte CRUD · Read. Ela usa a mesma permissão da lista, view_course, porque as duas só mostram dados. Se não fez o extra, pule essa classe e tire o DetailView do import.
Os dois juntos
O LoginRequiredMixin vem primeiro: quem não está logado vai para o login. Depois o PermissionRequiredMixin confere a permissão de quem já entrou.

3 Dar permissão a um usuário

No admin (/admin), abra Usuários, escolha o usuário e, em Permissões do usuário, adicione por exemplo Can view course e Can add course. Para vários usuários de uma vez, crie um Grupo com as permissões e coloque os usuários nele.

4 Botão Sair e botões por permissão

No course_list.html, logo abaixo do <h1>, entra o botão Sair. E os botões do CRUD só aparecem para quem tem a permissão, o que evita botão que leva a um 403. O template recebe as permissões em {{ perms }}:

{% extends "base.html" %}

{% block title %}Cursos{% endblock %}

{% block content %}
    <h1>Cursos</h1>
    <span>Olá, {{ user.username }}</span>
    <form method="post" action="{% url 'accounts:logout' %}">
        {% csrf_token %}
        <button type="submit" class="btn btn-sm btn-outline-secondary">Sair</button>
    </form>
    {# troque courses pelo nome do seu app #}
    {% if perms.courses.add_course %}
        <a href="{% url 'courses:course_create' %}" class="btn btn-warning">Novo curso</a>
    {% endif %}

    <ul>
        {% for course in courses %}
            <li>
                {{ course.name }}
                {% if perms.courses.view_course %}
                    <a href="{% url 'courses:course_detail' course.pk %}" class="btn btn-sm btn-secondary">Ver</a>
                {% endif %}
                {% if perms.courses.change_course %}
                    <a href="{% url 'courses:course_update' course.pk %}" class="btn btn-sm btn-primary">Editar</a>
                {% endif %}
                {% if perms.courses.delete_course %}
                    <a href="{% url 'courses:course_delete' course.pk %}" class="btn btn-sm btn-danger">Excluir</a>
                {% endif %}
            </li>
        {% empty %}
            <li>Nenhum curso cadastrado.</li>
        {% endfor %}
    </ul>

    {% if is_paginated %}
        <nav class="d-flex align-items-center gap-2">
            {% if page_obj.has_previous %}
                <a href="{% querystring page=page_obj.previous_page_number %}" class="btn btn-sm btn-outline-primary">Anterior</a>
            {% endif %}
            <span class="text-muted small">Página {{ page_obj.number }} de {{ page_obj.paginator.num_pages }}</span>
            {% if page_obj.has_next %}
                <a href="{% querystring page=page_obj.next_page_number %}" class="btn btn-sm btn-outline-primary">Próxima</a>
            {% endif %}
        </nav>
    {% endif %}
{% endblock %}
{{ user }}
O usuário logado. O Django manda ele para todo template, sem precisar passar na view.
"Olá" e Sair sempre visíveis
A view só monta a página para quem está logado. Quem não está vai direto para o login. Então o "Olá" e o botão Sair aparecem sempre.
Logout com <form method="post">
Desde o Django 5 o logout só aceita post. Um link comum (<a>) dá erro 405, por isso o botão Sair fica num formulário.
action
Para onde o formulário envia. Aqui o form está na lista, mas envia para a rota de logout.
Ver
Só se você fez o extra da DetailView. Fica dentro de {% if perms.courses.view_course %}, a mesma permissão da CourseDetailView. Como a lista também exige view_course, quem vê a lista sempre vê esse botão: o if deixa claro qual permissão a página do botão pede.
Novo curso
Fica fora do for, como antes, mas dentro de {% if perms.courses.add_course %}. Só aparece para quem pode cadastrar.

✓ Resultado esperado

Sem login, /courses/listar/ manda para a tela de login. Logado com uma conta nova, sem permissões, /courses/listar/ dá 403. Com só Can view course, a lista aparece, mas sem os botões Novo curso, Editar e Excluir, e abrir /courses/criar/ dá 403. Com o superusuário, tudo funciona.

Superusuário

O superusuário tem todas as permissões automaticamente, não precisa marcar nenhuma.

Esconder o botão não basta

O {% if perms %} só esconde o botão. Quem digitar a URL direto ainda chega na view, e é o PermissionRequiredMixin que bloqueia. Use os dois.
