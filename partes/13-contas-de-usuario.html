Sem models.py?

O Django já tem o model de usuário pronto (django.contrib.auth), com tabela criada na primeira migração. O accounts só precisa de views, rotas e templates.

O UserCreationForm pede só usuário e senha. Para pedir também e-mail, nome e sobrenome, crie um formulário que herda dele:

from django.contrib.auth.forms import UserCreationForm
from django.contrib.auth.models import User


class CustomUserCreationForm(UserCreationForm):
    class Meta:
        model = User
        fields = ["username", "email", "first_name", "last_name", "password1", "password2"]
UserCreationForm
Formulário pronto de cadastro, com as validações de senha do Django. Herdando dele, essas validações continuam valendo.
model = User
O model de usuário que já vem com o Django.
fields
Campos do formulário, na ordem em que aparecem. email, first_name e last_name já existem no User, só não vinham no formulário. password1 e password2 são a senha e a confirmação.

O Django já traz as views de login e logout prontas (LoginView e LogoutView). Basta configurar. O cadastro usa o formulário do passo anterior.

1 As views

from django.contrib.auth.views import LoginView, LogoutView
from django.urls import reverse_lazy
from django.views.generic import CreateView
from accounts.forms import CustomUserCreationForm


class UserLoginView(LoginView):
    template_name = "accounts/user_login.html"
    redirect_authenticated_user = True
    next_page = "nome_do_seu_app:person_list"


class UserLogoutView(LogoutView):
    next_page = "accounts:login"


class UserCreateView(CreateView):
    template_name = "accounts/user_form_create.html"
    form_class = CustomUserCreationForm
    success_url = reverse_lazy("accounts:login")
LoginView
Mostra o formulário de usuário e senha, confere no banco e faz o login.
redirect_authenticated_user
Quem já está logado e abre a página de login vai direto para o next_page.
next_page
Para onde ir depois de entrar (a lista de pessoas) ou depois de sair (a tela de login).
LogoutView
Faz o logout. Não tem template: sai e redireciona.
form_class
O formulário da página de cadastro, o CustomUserCreationForm do passo anterior.
CreateView
A mesma do passo 24, agora criando um usuário em vez de uma pessoa.

2 As rotas do accounts

from django.urls import path
from accounts.views import UserLoginView, UserLogoutView, UserCreateView

app_name = "accounts"

urlpatterns = [
    path("login/", UserLoginView.as_view(), name="login"),
    path("logout/", UserLogoutView.as_view(), name="logout"),
    path("cadastro/", UserCreateView.as_view(), name="register"),
]

3 Incluir no projeto

from django.contrib import admin
from django.urls import path, include

urlpatterns = [
    path('admin/', admin.site.urls),
    path('contas/', include('accounts.urls')),
    path('', include('nome_do_seu_app.urls')),
]
'contas/'
Prefixo das rotas: o login fica em /contas/login/, o cadastro em /contas/cadastro/.

        {{ form.as_p }}

✓ Resultado esperado

Acesse http://127.0.0.1:8000/contas/cadastro/, crie uma conta e entre com ela. Você cai na lista de pessoas. O botão Sair entra na próxima parte, junto com a proteção das views.

Senha recusada no cadastro?

O UserCreationForm não aceita senhas curtas, só com números ou parecidas com o usuário. A mensagem aparece embaixo do campo.
