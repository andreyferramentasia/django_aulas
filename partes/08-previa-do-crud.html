O Bootstrap é uma biblioteca de CSS pronta: você coloca classes no HTML (btn, table, container) e ganha botões e tabelas bonitos sem escrever CSS.

1 Importar via CDN

Um CDN (rede de distribuição de conteúdo) é um servidor público que hospeda arquivos como o Bootstrap. Em vez de baixar e guardar o CSS e o JS no seu static/, você só aponta para o endereço deles. O navegador baixa de lá ao abrir a página, e se a pessoa já visitou outro site que usa o mesmo arquivo, ele já vem do cache.

Copie as linhas do site oficial (getbootstrap.com, seção Include via CDN) e cole no <head>:

<link href="https://cdn.jsdelivr.net/npm/bootstrap@5.3.8/dist/css/bootstrap.min.css" rel="stylesheet"
    integrity="sha384-sRIl4kxILFvY47J16cr9ZwB07vP4J8+LH7qKQnuqkuIAvNWLzeN8tE5YBujZqJLB" crossorigin="anonymous">
<script src="https://cdn.jsdelivr.net/npm/bootstrap@5.3.8/dist/js/bootstrap.bundle.min.js"
    integrity="sha384-FKyoEForCGlyvwx9Hj09JcYn3nv7wiPVlz7YYwJrWVcXK/BmnVDxM+D2scQbITxI" crossorigin="anonymous"
    defer></script>
cdn.jsdelivr.net
O CDN que hospeda o Bootstrap. O @5.3.8 no endereço fixa a versão, assim o site não muda sozinho quando sair uma nova.
bootstrap.min.css
O CSS com todas as classes. O .min é a versão compactada, menor para baixar.
bootstrap.bundle.min.js
O JS dos componentes que se mexem: menus, modais, alertas que fecham. O bundle já inclui o Popper, usado nos menus.
integrity
Uma "impressão digital" do arquivo. Se o arquivo do CDN for alterado, o navegador não carrega. Copie exatamente como está.
crossorigin
Necessário para o integrity funcionar com arquivos de outro site.
defer
Carrega o JS sem travar a página.

E o Bootstrap 6?

Já existe o 6.0.0-alpha.1, mas é alpha: versão de teste, que ainda pode mudar classes e ter bugs. Por isso o tutorial usa a 5.3.8, a última estável. Quando a 6 sair estável, basta trocar as linhas do CDN pelas novas do site oficial.

2 Onde colocar

Essas linhas vão no <head> de toda página. Para não repetir em cada template, elas ficam no base.html, criado no próximo extra.

Sem internet?

O Bootstrap vem do CDN, então sem internet a página aparece sem estilo. O CRUD continua funcionando.

Toda página do site repete o mesmo começo (o <head> com o Bootstrap), o mesmo menu e o mesmo rodapé. Em vez de copiar isso em cada template, tudo fica num arquivo só, o base.html, e cada página preenche só o miolo.

1 A pasta de templates do projeto

O base.html é usado por todos os apps (courses e, depois, accounts), então ele fica numa pasta templates/ na raiz do projeto, ao lado do manage.py. O menu, a barra lateral e o rodapé ficam separados em partials/:

meu_projeto/
├── app/
├── courses/  # troque pelo nome do seu app
├── templates/
│   ├── base.html
│   └── partials/
│       ├── _navbar.html
│       ├── _sidebar.html
│       └── _footer.html
└── manage.py

O Django só procura templates dentro dos apps. Para ele achar essa pasta, coloque o caminho no "DIRS":

TEMPLATES = [
    {
        "BACKEND": "django.template.backends.django.DjangoTemplates",
        "DIRS": [BASE_DIR / "templates"],
        "APP_DIRS": True,
        ...
    },
]

? Entendendo o código

"DIRS"
Pastas extras onde o Django procura templates, além das pastas templates/ dos apps (APP_DIRS). O BASE_DIR já existe no topo do settings.py e aponta para a raiz do projeto.
{% load static %} e {% static '...' %}
O load libera a tag {% static %}, que monta o caminho do arquivo, ex.: /static/courses/css/style.css. Como o CSS é carregado no base.html, as outras páginas não precisam disso.
{% block title %} e {% block content %}
Espaços que cada página preenche. O texto dentro do block title (Meu projeto) é o padrão, usado quando a página não troca.
{% include %}
Cola o conteúdo de outro template naquele lugar. Assim o base.html fica curto, e mudar o menu é mexer num arquivo só.
_ no nome
Só um costume: o _ avisa que o arquivo é um pedaço de página, e não uma página inteira.
Classes do Bootstrap
navbar monta a barra do topo. row com col-md-3 e col-md-9 divide a tela em sidebar e conteúdo (o Bootstrap divide a linha em 12 partes). d-flex flex-column min-vh-100 no <body> e flex-grow-1 no meio empurram o footer para o fim da tela, mesmo com pouco conteúdo. O d-flex flex-column no container-fluid e o flex-grow-1 na row fazem a sidebar ir até o footer, em vez de parar onde o menu acaba.
{% if user.is_authenticated %}
A navbar aparece em todas as páginas, inclusive nas que não pedem login (como a tela de login, mais adiante). O if mostra o "Olá" só para quem entrou. O {{ user }} chega sozinho em todo template, sem passar pela view.
{% now "Y" %}
O ano atual. Assim o rodapé não precisa ser trocado todo ano.

4 Usar o base numa página

Cada página começa com {% extends %} e coloca o conteúdo dentro do block content. A partir da parte CRUD · Read, todos os templates seguem este formato:

{% extends "base.html" %}

{% block title %}Título da aba{% endblock %}

{% block content %}
    <h1>Título da página</h1>
{% endblock %}
{% extends "base.html" %}
Usa o base.html como molde. Precisa ser a primeira linha do template.
Fora dos blocks
Num template com extends, o que fica fora de um {% block %} não aparece.
